# New ERA版 下図 v2 設計メモ

対象ファイル：`new-era-diagram-v2.svg` / `new-era-diagram-v2.pdf`（A0横向き 1189×841mm、SVG はテキスト編集可能なまま）
生成方法：`gen-v2.py`（グリッド座標を定義して SVG を生成するスクリプト。本フォルダに保存）
内容の正は v1（`new-era-v1-notes.md` の参照点チェックリスト・根拠を全て引き継ぐ）。v2 の変更は**レイアウトとカテゴリ区画のみ**。

## v1 のバランス問題点（目視で具体化）

v1 を画像化して確認した問題：

1. **中心過密**：中段（SMSF／UDSF／UDM／NSSAAF 周辺、NEF—UDR—PCF 間）に線とラベルが集中し、斜めの長距離線が図全体を横断していた（AIOTF→UDR、NSSAAF→TSCTSF 等）。ラベルが箱に覆われて読めない箇所もあった（N30 は NWDAF の箱の中心、N33／N36／N87／N81 等も同様）
2. **左上の孤立と空白**：non-3GPP サブ図が左上に孤立して重く、その下〜中央左（LCS Client 周辺・GMLC 上方）に大きな空白があった
3. **SCP 配置例枠の疎密差**：枠が大きいのに内部が疎（NF(C)／NF(P) 間の空白）で、左中央の面積の割に情報が薄かった
4. **下辺の重量不足**：ユーザープレーン行の下（NG-RAN 下方〜フッター間）と右下（MB-UPF／DN 下方）に広い空白帯があった
5. **箱サイズのばらつきと無グリッド**：AMF・SEPP・EIF・AIOTF が大きく内部余白が多い一方で小型 NF が密集。行・列の基準線がなく階段状の配置だった
6. **上辺過重**：タイトル直下に大きな青箱3つ（AIOTF／EIF／SEPP）が並び、上辺に視覚重量が寄っていた
7. **パネルとの重量差**：右パネルは文字密度が非常に高い一方、本図の周縁（特に右上 SEPP 周辺・下辺）が軽かった
8. **カテゴリの不在**：RAN／CORE 等のドメイン区画がなく、要素の所属が読み取りにくかった（v2 への追加指示）

## v2 のレイアウト方針と対応

| v1 の問題 | v2 での直し方 |
|---|---|
| 1 中心過密・ラベル埋没 | NF を 6列×6行のグリッド（列間隔210、行間隔140）に整列し、中心の数セル（NEF の扇出しコリドー等）を意図的に空けた。線ラベルは全て最前面レイヤーに描き直し、箱に覆われるラベルは配置パラメータ（t／オフセット）を個別調整（N30／N33／N5／N36／N87／N81／N11／N6／N34／N55／N116／N117／AIOT1 他 約25件） |
| 2 左上の孤立・空白 | non-3GPP を左列上部のカテゴリゾーンとして本図に統合（サブ図扱いをやめ、ゲートウェイの N2／N3 は本図の AMF／I-UPF へ直接描画）。左列下部に CORE の左カラム（GMLC／LMF／CBCF／NSSF／NRF・SCP 枠）を連続配置し、左列の空白を解消 |
| 3 SCP 枠の疎密差 | 枠を 390×278 に縮小し、NRF／SCP を均等配置。枠の相対位置（左列下部、AMF の左上）は原図の骨格どおり維持 |
| 4 下辺の空白 | ユーザープレーン行（I-UPF／PSA-UPF／MB-UPF／DN）を CORE 下辺ストリップ＋DN ゾーンに組み込み、NG-RAN の下に仕様行（38.300／38.401）を置いて底辺まで構造を通した |
| 5 箱サイズ・無グリッド | 箱は階層別に統一（標準 NF 170×58、右列 160×58、大箱 AMF 214×80／UDM 204×78、NG-RAN 枠 414×266）。全 NF がグリッド交点に乗り、行・列が揃った |
| 6 上辺過重 | 上段はカテゴリゾーンの帯（AMBIENT IoT／CORE バンプ／IMS）に再編。EIF／SEPP は CORE のバンプ（上部突起）内に収め、AIOTF／ADM は AMBIENT IoT ゾーンへ分離 |
| 7 パネルとの重量差 | 右パネルの略語表は v1 と同内容のまま字サイズのみ調整して枠内に収納。左パネル下部に Categories 凡例を追加し、左下の余白を解消 |
| 8 カテゴリ不在 | 下記のゾーン区画を新設 |

原図の骨格の維持：AMF は左下のハブ（グリッド左下）、UDM は中央左（ARPF／SIDF 内包）、SMF は右下、PSA-UPF は SMF の真下、PCF は右中央、NEF は中央上部、NRF／SCP は AMF の左上、ユーザープレーンは最下段——v1 が原図から踏襲した相対位置はそのまま。

## カテゴリ（ドメイン）区画

小川さんの原図のドメイン表記（CS／PS／EPC／5GC／IMS のラベルで領域を示す流儀）に倣い、薄い面色＋左上角の見出しタブで区画した。カテゴリ名は英語表記。凡例は左パネル下部「Categories」に説明付きで収録。

| カテゴリ | 区画の置き方 | 所属ノード |
|---|---|---|
| UE / DEVICES | 左下の独立ゾーン | UE、AIoT Device |
| RAN | 左下、UE の右に独立ゾーン | NG-RAN（内部：DU×2、CU-CP、CU-UP、ng-eNB） |
| CORE — 5GC | 本図の主体。L字型の大きな区画（左カラム＋中央＋下辺ストリップ＋上部バンプ） | AMF、SMF、I-SMF、I-UPF、PSA-UPF、PCF、NEF、NRF、SCP、UDM、UDR、UDSF、AUSF、SMSF、NSSF、NSSAAF、5G-EIR、LMF、GMLC、CBCF、SEPP、NWDAF、DCCF、MFAF、ADRF、UCMF、NSACF、TSCTSF、TSN AF、EASDF、5G DDNMF、AANF、EIF、NSWOF、CHF、BSF、AF |
| NON-3GPP ACCESS | 左列上部の独立ゾーン（23.501 §4.2.8） | UE スタブ（破線）、Untrusted non-3GPP、TNAP、TWAP、N3IWF、TNGF、TWIF、W-AGF、5G-RG / FN-RG |
| AMBIENT IoT | 上段左の独立ゾーン | AIOTF、ADM |
| IMS — VoNR | 上段右の独立ゾーン | P-CSCF、I-CSCF、S-CSCF、AS |
| MBS | CORE 内のサブゾーン（右下） | MB-SMF、MB-UPF、MBSF、MBSTF |
| DN / EXTERNAL | 右下の独立ゾーン | DN |

### 複数カテゴリに跨る要素の主所属と注記

- **AIOTF／ADM**：主所属は AMBIENT IoT（Rel-19 の新規ドメインとして独立ゾーン化）。ただし両者は 5GC の NF でもあり、AIOT3（→AMF）等の線は CORE へ跨る。ゾーン内に「AIoT Device → UE / DEVICES · AIoT reader in NG-RAN」の相互参照注記を入れた
- **AIoT Device**：主所属は UE / DEVICES（端末側の実体のため）。AMBIENT IoT とは AIOT1（破線）で接続し、上記の相互参照注記で補う
- **NG-RAN**：主所属は RAN。AIoT reader を内包するため AMBIENT IoT とも関係する（枠内注記に「AIoT reader」を明記済み）
- **AF**：主所属は CORE（23.501 §6.2 の NF として収録）。IMS の P-CSCF は AF と同一視される点（N5）を IMS ゾーン内の注記「P-CSCF = AF (N5)」で示した
- **MB 系**：主所属は MBS（CORE のサブゾーンとして区画し、凡例にも「multicast / broadcast (in CORE)」と明記）
- **LCS Client**：外部システムだが、描画位置は接続先 GMLC の直上（CORE 左カラム内、破線箱）。主所属は DN / EXTERNAL 相当の外部として扱い、配置のみ GMLC 近傍とした
- **SEPP**：主所属は CORE（バンプ内）。PLMN 間接続は N32 スタブ＋右パネルの Inter-PLMN Security 小図で表現

## 内容の欠落がないことの確認方法と結果

確認方法：v1／v2 両 SVG の全テキスト要素を抽出し、文字列の多重集合（multiset）で差分を取った。

- **参照点ラベル・NF キャプション・パネル文言は全て一致**（差分リストに現れたのは下記の意図的な置き換え・追加のみ）
- v1 にあって v2 に無い文字列と、その扱い：
  - タイトル注記行 → v2 版の文言に差し替え（「Draft v2 — balanced layout with category zones」を追記）
  - 「Draft v1 — …」→「Draft v2 — …」に更新
  - 「5GC non-3GPP Access (23.501 §4.2.8)」→ ゾーン見出し「NON-3GPP ACCESS」＋区画内注記「23.501 §4.2.8」に分割（内容は保持）
  - 「IMS for VoNR (23.228)」→ ゾーン見出し「IMS — VoNR」＋ IMS 注記内の (23.228) で保持
  - 「5GC」（浮遊ラベル）→「CORE — 5GC」ゾーン見出しに置き換え
  - 「ISMF」→「I-SMF」（同一実体、キャプション「29.502 Nsmf」は同一）
  - 「DU1／DU2／CUCP／CUUP／NGENB」→ v1 では併記されていた無ハイフン表記。v2 は「DU／DU／CU-CP／CU-UP／ng-eNB」のハイフン表記に統一（実体5件は保持）
- v2 で追加した文字列：カテゴリ見出し・凡例（Categories）、TSN AF の箱とキャプション、Nnrf の線ラベル、SWa' の注記「to WLAN」、DN の注記「Data Network」、AMBIENT IoT ゾーンの相互参照注記
- テキスト要素数：v1 = 457、v2 = 482（追加は上記のカテゴリ・凡例・TSN AF 等）

### v2 で新規に追加した内容（v1 SVG には無かったもの）

- **TSN AF の箱**：TS 23.501 §6.2 の NF 一覧に含まれるが、v1 の SVG には箱が存在しなかった（v1 notes の「39件全収録」と食い違う）。v2 で右列に箱を追加。§4.2 に専用参照点が無いため線は引かず、キャプション「via NEF / PCF」で接続形態を示した
- **Nnrf の線ラベル**：v1 notes では SCP 配置例枠内の SBI 線として記載されていたが、v1 SVG にラベルが無かった。v2 で NRF—SCP 線にラベルを付与

## v2 時点の残課題（完成図の段で調整）

- AMF ハブ周辺（AMF 上部〜5G-EIR 間）は線の集束により依然として最も密。フォントを落とさず配置で解く方針のため、完成図では AMF の大型化または周辺 NF の再配分が候補
- EIF のキャプション「29.566 Neif」に EIF 自身の線が重なる（v1 から継続）
- 右下象限（MBS／DN ゾーン）は構造的に疎で、密度測定でも最軽。MBS ゾーンの縦圧縮で CORE 下辺とのバランスを取り得る
