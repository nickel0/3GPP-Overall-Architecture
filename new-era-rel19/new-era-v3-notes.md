# New ERA版 下図 v3 設計メモ

対象ファイル：`new-era-diagram-v3.svg` / `new-era-diagram-v3.pdf`（A0横向き 1189×841mm を実測確認、SVG はテキスト編集可能なまま）
生成方法：`gen-v3.py`（`gen-v2.py` を土台に改修。座標の正本は v2 のグリッド配置のまま）
v3 の変更は2つだけ：**(1) スタイル変更（カテゴリゾーンの背景塗り廃止＋線を最前面へ）**、**(2) 法的傍受（LI）の追加**。レイアウトと v2 の内容は正として変えていない。

## 1. スタイル変更（ユーザー指示「背景塗らないほうがいいんでない？ または、線を一番上に」→ 両方実施）

| 対象 | v2 | v3 |
|---|---|---|
| カテゴリゾーン（UE / DEVICES、RAN、CORE — 5GC、NON-3GPP ACCESS、AMBIENT IoT、IMS — VoNR、MBS、DN / EXTERNAL）の背景 | 薄い面色（8色の tint） | **面色を全て外し**、細い枠線（ZONE_STROKE）＋見出しタブだけで区画 |
| ゾーン見出しタブ | 濃色（#37474f）塗り＋白文字 | 白地＋細枠＋濃色文字（読める最小限の塗り） |
| 線（インターフェース）の描画順 | 箱より下（線 → 箱 → ラベルの順） | **全ての線を箱より上の最前面レイヤーへ移動**（線ラベルは v2 から最前面のまま）。箱や枠に線が隠れる箇所は無くなった |
| 左パネル Categories 凡例の色チップ | ゾーン tint と同色 | ゾーン無地化に合わせ白チップに変更（文言は不変） |

### NF 箱自体の塗りについての判断

**変更なし（判断と根拠）**：v2 時点で NF 箱の塗りは全て白（`#ffffff`）で、リリース別の色分け（黒＝〜Rel-17／緑＝Rel-18／青＝Rel-19）は**枠線と名前文字の色**が担っていた。したがって箱の塗りを薄くする必要は元々なく、線を最前面化したことで可読性の問題も解消した。色分けの判別は v3 でも枠・文字色で従来どおり可能。

### 可読性の確認結果（PNG 画像化して目視）

- 全体図＋密集部3か所（AMF ハブ周辺、上段 AIOTF／EIF／SEPP 周辺、SCP 配置例枠）を拡大確認
- 線・線ラベルが箱に隠れる箇所は解消（v2 で箱の下に潜っていた線が全て見える）
- 代償として、v2 では白い箱に隠れていた「箱を横切る線」が見えるようになった（例：5G-EIR の箱を斜めに横切る線、NSWOF 左上隅など）。これは「線を一番上に」の指示の必然的な帰結として受け入れ、下図段階では配置で解かない（v4 の有機的配置で根本対処する方針、下記 §5）

## 2. 法的傍受（LI）の追加

v2 まで未収録だった LI を追加した。根拠仕様が TS 23.501 でなく **TS 33.127** のため漏れていたもの。

### 取得・確認した仕様

- TS 33.127 **V19.8.0**（Rel-19 最新版）を 3GPP archive から取得（`../specs/33127-j80.zip` / `.docx` / `.txt`）
- 確認した条項：§5.2（全体アーキテクチャ）、§5.3.4（MDF）、§5.3.5（ADMF＝LICF／LIPF 等を内包）、§5.4.3（LI_HI1）、§5.4.4（LI_X1）、§5.4.5（LI_X2）、§5.4.6（LI_X3）、§5.4.8／§5.4.9（LI_HI2／LI_HI3）、§6.2.1（5G core-anchored LI）、§6.2.2.1（LI at AMF）、§6.2.3.1（LI for SMF/UPF）

### 描いたもの

- **ゾーン**：「LI — LAWFUL INTERCEPTION」を新設（他のゾーンと同じ枠線＋タブ形式、背景塗りなし）
- **ADMF**：箱内に「LICF · LIPF」チップを内包（§5.3.5。LICF が令状を受け、LIPF がプロビジョニングの代理）
- **MDF2／MDF3**：ADMF の下に縦積み
- **POI の内蔵注記**（灰色小文字を箱内左上に配置）：AMF に「IRI-POI」（§6.2.2.1）、SMF に「IRI-POI · CC-TF」（§6.2.3.1）、I-UPF／PSA-UPF に「CC-POI」（§6.2.3.1）
- **線（全て点対点、ラベル付き）**：
  - LI_X1：ADMF → MDF2、ADMF → AMF、ADMF → SMF（LIPF によるプロビジョニング、§5.4.4／§6.2.2.1／§6.2.3.1）
  - LI_X2：AMF → MDF2、SMF → MDF2（xIRI の転送、§5.4.5）
  - LI_X3：PSA-UPF → MDF3（xCC の転送、§5.4.6）
  - LI_T3：SMF → PSA-UPF（CC-TF から CC-POI へのトリガ、§6.2.3.1）。N4 と同一 NF 対のため、線は SMF–PSA-UPF の区間を N4 と共有し、ラベルを別位置に分けた
  - LI_MDF：MDF2 — MDF3（§5.3.4）
  - スタブ（外部宛て）：ADMF から LI_HI1（LEA からの令状、§5.4.3）、MDF2 から LI_HI2（IRI を LEMF へ、§5.4.8）、MDF3 から LI_HI3（CC を LEMF へ、§5.4.9）。LEMF 自体は箱として描かず、既存のローミング系スタブと同じ流儀にした
- **凡例・略語表**：左パネル Categories に LI の行を追加。右パネル略語表に ADMF／LICF／LIPF／MDF2／MDF3／LEMF の6件を追加

### 配置の判断と理由

LI ゾーンは **CHF の下、MBS ゾーンの右隣の空き帯**（図の右側、DN / EXTERNAL ゾーンの上）に縦積みで置いた。理由：(1) この帯が本図で唯一、箱3つ分の連続した空白だった、(2) ADMF から AMF／SMF／UPF への線が西向きに扇出でき、既存ボックスの**名前文字を横切らない**経路（y≈1065 の空き行帯）を確保できた、(3) LEMF 宛てスタブを右端から外向きに出せる。

### 色の扱い

**黒（〜Rel-17 の色）**。LI は Rel-18／19 の新規導入ではなく、TS 33.107 系譜の基礎機能で 5G では Rel-15 から存在するため、リリース色分けでは「既存仕様の範囲」として黒にした（新規の色は作らない）。

### 描かなかったもの（根拠はあるが省略したものと、その理由）

- **ADMF → MDF3 の LI_X1**（§6.2.3.1 で LIPF が MDF3 もプロビジョニング）：直線を引くと MDF2 の箱を縦断するため省略。ADMF → MDF2 の LI_X1 で代表させた
- **ADMF → UPF の LI_X1**：§6.2.3.1 NOTE 2 の監視用途のみで、CC-POI への主たる設定経路は CC-TF 経由の LI_T3 のため省略
- **LI_SI（LIPF — NRF 内 SIRF）**（§6.2.2.1／§6.2.3.1、"may interact" の発見用）：図を横断する長距離線になるため省略
- **LI_X0／LI_NO 等のライフサイクル管理系**（§5.6、仮想化・MANO 連携）：アーキテクチャ図の主題から外れるため省略
- **単独の TF／IEF／ICF／LARF／IQF 等**：汎用アーキテクチャ（§5）の要素で、5G core-anchored の部分集合（§6.2.1／§6.2.2.1／§6.2.3.1）に対象を絞った。SMF 内の CC-TF は注記で表現
- **CC-PAG**（§8.6.2 の任意拡張）：省略

### 既知の擦り（下図段階、v4 で配置ごと解く）

- LI_X3 の線が MBSTF の右下隅を小さくかすめる
- LI_X1（ADMF → SMF）の線とラベルが MB-SMF の上端帯・キャプション右端にかかる
- LI_X1（ADMF → AMF）／LI_X2（AMF → MDF2）の線が NSACF／I-SMF の上端帯（名前文字の上）を通る

## 3. 内容の欠落がないことの確認（テキスト多重集合差分）

v2／v3 両 SVG の全テキスト要素を多重集合で差分検証（482 件 → 516 件）。

- **v2 にあって v3 に無い文字列は2件のみ**：タイトル注記の「Draft v2 — …」と右パネルの「Draft v2 — prepared for review.」で、いずれも Draft v3 版の文言への意図的な差し替え
- **v3 の追加分は全て意図したもの**：バージョン文言2件、LI のゾーン見出し・箱名・チップ・POI 注記・線ラベル（LI_X1×3／LI_X2×2／LI_X3／LI_T3／LI_MDF／LI_HI1–3）・Categories 凡例1行・略語表6件
- ゾーン tint の色コード（#f4f7fb 等6色）は SVG 内から消滅したことを確認。タブの濃色 #37474f は文字色としてのみ残存
- 描画順：エッジの `<line>` 群がノードの `<rect>` 群より後に出現することを確認（最前面化）

- **N70／N71（SBA in IMS）**：相手先未照合のため線は引かず、IMS ゾーン内の注記のみ

- **BSF の常時掲載要否**：原図にも載っているため掲載を継続（要判断事項のまま）
- AMF ハブ周辺が依然として最も密、EIF キャプションへの線の重なり、右下象限（MBS／DN）が構造的に疎、という v2 の残課題も継続

## 5. v4 への方針（ユーザー評価・提案を受けた申し送り、v3 では対応しない）

1. **グリッド整列をやめ、有機的な配置へ**（ユーザー評価「グリッド整理は画一的すぎて分かりづらい」）：厳密なグリッド整列を廃し、小川さんの原図のように、機能の近さとトラフィックの流れで置き、箱の大きさも重要度で変える
2. **最初から A0 実寸をキャンバスにして設計する**（ユーザー提案「A0向けにフォーマットして書かないか」）：任意キャンバスで描いて A0 に拡大するのではなく、A0 実寸（1189×841mm）をキャンバスとして書き、フォントサイズ・線幅を印刷時の実寸ポイント／mm で設計する。最小文字の下限も実寸で決める
