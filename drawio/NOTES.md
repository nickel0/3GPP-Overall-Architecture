# draw.io 版 設計メモ

対象：
- `3gpp-overall-architecture.drawio` — 原図 Release-17 までの draw.io 再現（マスター）
- `3gpp-overall-architecture-rel19-composite.drawio` — マスターに Release-18／19 の差分を累積追加した全部入り最新版（複合盤）。設計は末尾の「複合盤」の節。

## 方式：pptx 機械抽出 → mxGraph XML 変換（手作業の描き写しなし）

- `tools/extract_full.py`：pptx の slide1 XML を直接解析。グループ変換を平坦化し、全図形の絶対座標・サイズ・preset 形状・塗り・線（色／太さ／破線／矢印）・テキスト（ラン単位のサイズ・太字・色、段落の揃え、テキストボックスの折り返し・余白・縦位置）・回転・反転・コネクタの接続参照・フリーフォームのパス・表（graphicFrame、セル単位の罫線・塗り・余白）を抽出。色はテーマ色に解決し lumMod／lumOff／tint／shade も適用。
- `tools/gen_drawio.py`：抽出 JSON から mxGraph XML を生成し、テキスト一致を自動検証する。
- 座標系：レイアウトは pt で計算し、draw.io 単位（CSS px @96dpi）へ ×4/3 して書き出す。ページは draw.io の A0 プリセット（4494×3179 px＝1189×841 mm）そのもの。原図スライド（554.5×311.9 mm）は幅いっぱいに拡大（×2.145、フォント・線幅も同率）し、上部にタイトル帯を確保。ページ全面に白の背景セル（ロック済み）を置き、書き出し範囲＝A0 ページになるようにしている。
- z 順：原図の文書順で出力（線の多くが NF の白箱の下を通る原図の重なりを再現）。

## 検証結果

- pptx の要素：図形 555＋コネクタ 246＋表 4。全数が draw.io セルに変換される（表はセル単位）。
- **テキスト欠落ゼロ**：テキストを持つ要素 572件（図形＋表セル）すべてで、pptx 側と .drawio 側の値が（空白正規化後）完全一致。生成のたびに自動検証する。
- 再現性：同じ pptx から抽出 JSON・.drawio がバイト単位で同一に再生成されることを確認。

## 変換の近似・割り切り

1. **コネクタ端点**：接続点 idx からの推定はやめ、コネクタ自身の xfrm（位置・反転・回転）から原図で描かれている端点を求め、接続先セルとの接続は保ったまま `exitX/exitY`・`entryX/entryY`（`exit/entryPerimeter=0`）でその点に固定した。原図コネクタの接続端 414件すべてが接続先の枠上／枠内に収まり、補正（クランプ）が要ったものは 0件。エルボーコネクタ 6件は中間点（waypoints）も原図の形で与えている。
2. **ブラケット 11件**（`[` 9件・`]` 2件）：draw.io 現行版には `mxgraph.basic.l_bracket`／`r_bracket` というステンシルが無い（初版で使っていた名前。開くと四角になる）。標準シェイプ `partialRectangle` の片側を開いた形（`[`＝right=0、`]`＝left=0）に置き換えた。
3. **フリーフォーム 10件**（大きな枠線・斜め区切り線）：draw.io に任意多角形の頂点シェイプが無いため、折れ線エッジとして再現。
4. **円弧 1件**：折れ線で近似。
5. 回転テキスト 2件は rotation 属性で再現。グループ構造は平坦化（見た目と編集可能性を優先）。
6. マスターに原図に無い要素として追加したのはヘッダー（タイトル＋「faithful reproduction」注記）のみ。

## 印刷（A0 PDF）

- `tools/export_pdf.py IN.drawio OUT.pdf` で A0 横の実寸 PDF（MediaBox 3370.39×2383.94 pt＝1189×841 mm、1ページ）を出す。`export/` に書き出し済み。
- 理由：draw.io デスクトップ版 CLI（Electron の printToPDF）は 1 px→0.72 pt で出力し、PDF では `--scale` が効かない。素の書き出しは A0 の 96% になるため、`--width 4681`（＝4494÷0.96）で出力し、pypdf で A0 幅にぴったり合わせて（×0.9995）MediaBox を A0 に設定している。
- 実行メモ：ヘッドレス環境では `xvfb-run` が必要。セッション D-Bus が応答しない環境（WSL 再起動直後など）では Electron が起動直後に無言で固まるため、スクリプトは `DBUS_SESSION_BUS_ADDRESS=disabled:` で起動している。
- 手で書き出す場合：draw.io の「ファイル → エクスポート → PDF」で「ページ」を選び、拡大率 100%。

## フォント

- 原図の指定：欧文は Arial（ラン 1,114件）、和文用（ea）は Noto Sans JP。一部（192 ラン）は欧文側も Noto Sans JP 指定。図中テキストに和文の文字は含まれない（0文字）。
- draw.io 版はすべて `fontFamily=Arial` に統一。和文フォントの指定は再現していないが、和文の文字が無いので表示上の欠落は起きない。Noto Sans JP 指定だった欧文ラン 192件は Arial で表示されるため、字形・字幅がわずかに原図と異なる。
- 書き出した PDF にはフォントがサブセット埋め込みされる（印刷所側でのフォント準備は不要）。Arial が無い環境では、計量互換の Liberation Sans に置き換わって埋め込まれる（字幅は Arial と同じため、改行位置・レイアウトは変わらない）。本リポジトリの `export/` の PDF も Liberation Sans 埋め込みで書き出している。
- Arial そのものの字形で刷りたい場合は、Arial の入った環境（Windows／macOS の draw.io）で書き出し直す。

### 追加線

- **経路を引いた線（16件）**：EIF の N110／N111／N112／N113／N114、Ambient IoT の AIOT1（論理参照点のため破線）／AIOT2／AIOT3／AIOT4／AIOT6／AIOT7／AIOT8、Rel-18 の N89（TSCTSF–AMF）、NCR の gNB control、NR Femto の N2／N3。
  経路は、原図の箱・文字・表を障害物、原図の線を「横切れるが沿っては走らない」コストとして扱う直交経路探索で下引きし、交差の多かった長距離線（AIOT2／AIOT3、N89 ほか）は waypoints を手で詰めた。結果は `tools/composite_routes.json` に固定し、生成時はこの経路をそのまま使う（draw.io の自動再ルーティングは使わない：`edgeStyle=none`＋端点固定）。
- **遠隔参照点のスタブ（4組）**：N96（TSCTSF–NRF）、AIOT5（AIOTF–NRF）、N116（SCP–NWDAF）、N117（SCP–DCCF）。相手が図の反対側（Annex G の NRF／SCP の例示）にあり、引くと図を横断する長距離線になるため、原図自身の「to/from X」の書き方にならい、両端の箱から短い線を出して先端に同じ参照点名を置いた（読み手は名前で両端を結ぶ）。
- N97／N99 は NSACF 右辺の短い線＋文字（other PLMN／same PLMN）、Nupf は PGW-U (PSA-)UPF 上辺の緑チップ。
- 機能節レベルの追加（Rel-18：§5.20b–d／§5.28a／§5.35A／§5.43–5.46／eRedCap／DetNet／XR 等、Rel-19：§4.2.18／§5.48／§5.49／§5.51／§5.52／サイドリンク multi-hop／LP-WUS・WUR／SBFD／AI/ML 等）はページ下帯の Release-18／Release-19 additions 一覧に収録。

### 色の意味

原図では緑＝Rel-16・青＝Rel-17 として既に使われており、追加分の緑＝Rel-18・青＝Rel-19 と二重の意味になる。現状はページ下帯の Colour note で明示し、追加ボックスは白塗り＋色枠＋色文字で原図の NF と見分けられるようにしている。色相をずらす等の根本対処はレビューでの確認事項。
